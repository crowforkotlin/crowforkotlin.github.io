uni-app SCSS 容器与 Flex 布局：从页面根节点到 Kotlin Compose

发表于2026-09-07|更新于2026-09-07|UniApp
|总字数:5.7k|阅读时长:22分钟|浏览量:|评论数:

在 uni-app 中，页面布局通常从一个根 <view> 开始，再由 SCSS 决定它如何占满屏幕、排列子节点和处理滚动。下面这段代码可以作为页面容器的起点：

本文以普通 .vue 页面的 H5、App WebView 和微信小程序为讨论范围，不把它直接当作 nvue 或 uni-app x 的样式规范。display、position、flex 都属于 CSS；SCSS 提供变量、嵌套和 mixin，编译后才交给目标端的样式系统处理。对照使用 Android Jetpack Compose，Kotlin 片段省略常规 import；示意的 Header、Content 是接收 Modifier 的自定义组件。

<template>
  <view class="pages-container">
    <view class="pages-container__header">标题</view>
    <view class="pages-container__content">
      <text>页面内容</text>
    </view>
  </view>
</template>

<style scoped lang="scss">
.pages-container {
  box-sizing: border-box;
  position: relative;
  display: flex;
  flex-direction: column;
  align-items: center;
  min-height: 100vh;
  width: 100%;
}

.pages-container__content {
  width: 100%;
}
</style>

这里的类名只描述结构，不要求所有页面都使用同一个名字。项目中已有 PageShell 时，应让页面把内容放入 PageShell 的插槽，由 PageShell 统一处理背景、安全区和滚动；业务页面只负责自己的内容容器。

pages-container 不是 uni-app 的内置类，也不具有继承关系。布局层级来自 template 的实际节点；SCSS 嵌套不会创建容器。

一、父布局和子布局分别负责什么

父容器负责回答三个问题：子元素沿哪个方向排列、交叉轴如何排列、自己占多大空间。子容器负责自己的内部排列，不应依赖页面外层的偶然样式。以下页面假设已在脚本中导入 ProfileCard：

<template>
  <view class="profile-page">
    <view class="profile-page__main">
      <ProfileCard />
    </view>
  </view>
</template>

<style scoped lang="scss">
.profile-page {
  display: flex;
  flex-direction: column;
  min-height: 100vh;
  box-sizing: border-box;
}

.profile-page__main {
  width: 100%;
  box-sizing: border-box;
  padding: 32rpx;
}
</style>

子组件的根节点也应该有明确的根类名，而不是直接依赖 view 标签：

示例头像需要项目提供 /static/avatar.png，也可以替换成自己的资源地址。

<!-- ProfileCard.vue -->
<template>
  <view class="profile-card">
    <image class="profile-card__avatar" src="/static/avatar.png" />
    <view class="profile-card__body">
      <text class="profile-card__name">Crow</text>
      <text class="profile-card__description">uni-app developer</text>
    </view>
  </view>
</template>

<style scoped lang="scss">
.profile-card {
  display: flex;
  align-items: center;
  width: 100%;
  box-sizing: border-box;
}

.profile-card__avatar {
  width: 96rpx;
  height: 96rpx;
  flex: 0 0 auto;
}

.profile-card__body {
  display: flex;
  flex-direction: column;
  min-width: 0;
  margin-left: 24rpx;
  flex: 1;
}
</style>

min-width: 0 很重要。Flex 子项默认可能不愿意缩小到内容以下，长文本就会把横向布局撑破；设置为 0 后，子项才会在父容器内收缩，文字再配合 text-overflow 或换行规则处理。

这个例子包含两层独立的 Flex：.profile-card 横向排列头像和正文；.profile-card__body 纵向排列两段文字。父元素设置 display: flex 不会让所有后代自动成为 Flex 容器，flex-direction 也不会从父元素继承下来。

子组件的根容器没有统一的必填属性

组件的用途 根容器可采用的写法 使用条件
表单、卡片等随内容变高的组件 width: 100%; box-sizing: border-box 希望填满父级内容宽度
固定头部下方的内容组件 flex: 1; min-height: 0 实际根节点参与父级列 Flex 布局，父级高度有界
横向条目中的正文 flex: 1; min-width: 0 实际根节点参与父级行 Flex 布局
图标与短文字组成的紧凑项 按内容决定尺寸，按需加 display: flex 不要求填满父级
包含角标的组件 position: relative 内部有相对该容器放置的绝对定位元素

width: 100% 与左右 margin 同时使用仍然可能溢出，因为 border-box 不包含 margin。不要给普通卡片根节点直接加 height: 100vh，这会让每张卡片至少接近一个视口的高度。

在 Vue 的 H5 单根组件中，父组件传入的 class 通常会合并到子组件根节点；多根组件和 inheritAttrs: false 会改变这种行为。小程序还存在组件宿主节点及样式隔离规则。因此跨端布局应明确组件的根尺寸接口，或使用父级 <view> 控制外部占位，不假定所有平台都会以相同方式透传 class。

二、示例属性逐项解释

.pages-container {
  box-sizing: border-box;
  position: relative;
  display: flex;
  flex-direction: column;
  align-items: center;
}

box-sizing: border-box 让指定的 width 和 height 包含 padding 与 border。例如宽度为 100% 且左右各有 32rpx 内边距时，元素不会因为内边距再次向外溢出。它不会自动继承给子节点。

以 width: 300px; padding: 20px; border: 2px solid 为例：content-box 下外宽为 344px；border-box 下外宽为 300px，内容宽为 256px。这里忽略 margin。

Compose 没有对应的 box-sizing 开关。Modifier.width(300.dp).padding(20.dp) 表示在父约束允许时先确定外宽，再从中扣除内边距；Modifier.padding(20.dp).width(300.dp) 把 padding 放在宽度限定之外，父约束允许时总宽可达 340.dp。Modifier 的顺序会改变测量结果，不能用 CSS 声明的先后顺序类比。

position: relative 让元素保留普通流中的占位，并可为绝对定位后代建立包含块。不设置偏移时，视觉位置不变；设置 top 或 left 后会移动绘制位置，但原来的占位仍保留。绝对定位元素使用最近的、满足条件的祖先包含块；transform 等属性也可能建立包含块，因此不一定以直接父元素为参考。

Compose 中对应的覆盖场景通常使用 Box，再用 Modifier.align(Alignment.TopEnd) 或 offset 放置子项。不过 Box 中的普通子项可以参与父级测量，CSS 的绝对定位元素不参与正常流尺寸计算，两者并非严格等价。

display: flex 把元素变成 Flex 容器，直接子元素成为 Flex 项。Compose 中对应 Row 或 Column，而不是给 Modifier 设置一个 display 属性。

flex-direction: column 让主轴从上到下。Compose 对应 Column；默认方向是垂直排列。flex-direction: row 对应 Row。

align-items: center 在交叉轴居中。column 的交叉轴是水平方向，所以示例中的子元素会水平居中。Compose 中 Column(horizontalAlignment = Alignment.CenterHorizontally) 表达同样的意思。

对于普通竖排页面，更常见的起点是 align-items: stretch，也可以省略这一行，使用 Flex 的默认拉伸行为。拉伸适用于交叉轴尺寸为 auto 的子项；显式宽度、min/max 限制仍会影响结果。改成 center 后，未声明宽度的子项通常不再横向拉满，所以开头的示例特意给内容区写了 width: 100%。

Compose 的 Column 默认不会把每个子项都拉满宽度，需要在相应子项上写 Modifier.fillMaxWidth()。这是从 Compose 转到 CSS 时容易忽略的差异。

注意：align-items 不控制主轴间距，也不等同于“整个页面水平垂直居中”。要在列布局中同时居中，通常还需要 justify-content: center，且容器高度必须有剩余空间；Compose 则写 verticalArrangement = Arrangement.Center。

下面是开头页面容器的近似 Compose 写法，额外的 fillMaxSize() 表示由页面约束提供屏幕空间：

Column(
    modifier = Modifier.fillMaxSize(),
    horizontalAlignment = Alignment.CenterHorizontally,
    verticalArrangement = Arrangement.Top,
) {
    Text("标题")
    Column(modifier = Modifier.fillMaxWidth()) {
        Text("页面内容")
    }
}

position: relative 没有直接翻译成 Modifier，因为这个例子没有覆盖元素。布局属性应根据实际需要添加。

覆盖元素：CSS 定位与 Compose Box

例如，在预览区域右上角放一个状态标签：

<template>
  <view class="preview">
    <text>预览内容</text>
    <text class="preview__badge">已完成</text>
  </view>
</template>

<style scoped lang="scss">
.preview {
  position: relative;
  width: 100%;
  height: 320rpx;
}

.preview__badge {
  position: absolute;
  top: 16rpx;
  right: 16rpx;
}
</style>
Box(modifier = Modifier.fillMaxWidth().height(160.dp)) {
    Text("预览内容")
    Text(
        "已完成",
        modifier = Modifier
            .align(Alignment.TopEnd)
            .padding(top = 8.dp, end = 8.dp),
    )
}

上面的数值只表示相近的视觉意图。CSS 的 right 指物理右侧，Compose 的 End 会随文字方向变化；从左到右的界面中两者位置一致。需要叠放时才使用 Box 或绝对定位，普通上下排列继续使用 Column 或列 Flex。

三、Flex 的两个轴

Flex 始终有主轴和交叉轴：

下面按常见横排书写、从左到右的界面说明；CSS 的 direction、writing-mode 和 reverse 方向会影响起止方向。

CSS flex-direction: row flex-direction: column
主轴 水平 垂直
交叉轴 垂直 水平
主轴对齐 justify-content justify-content
交叉轴对齐 align-items align-items

最常见的顶部布局如下：

.page {
  display: flex;
  flex-direction: column;
  min-height: 100vh;
}

.page__content {
  flex: 1;
}

父元素使用列布局，内容区使用 flex: 1 占据剩余高度。Compose 写法是：

Column(modifier = Modifier.fillMaxSize()) {
    Header()
    Content(modifier = Modifier.weight(1f))
}

浏览器通常把 flex: 1 展开为 flex-grow: 1; flex-shrink: 1; flex-basis: 0%，常用于“固定头部 + 可伸展内容”。但 min-height: 100vh 只是下限，不等同于固定的可用高度。需要稳定地分配局部滚动区的高度时，应使用确定高度，并给相关 Flex 子项设置 min-height: 0：

.page--static {
  display: flex;
  flex-direction: column;
  height: 100vh;
  min-height: 0;
  overflow: hidden;
}

.page--static__content {
  flex: 1;
  min-height: 0;
  overflow: hidden;
}

参考项目的 PageShell 正是这种结构：静态页面使用 height: 100vh，内容区使用 flex: 1、min-height: 0 和 overflow: hidden。缺少 min-height: 0 时，子内容可能以自身最小高度撑开父容器，滚动区域就无法收缩。

flex-grow：多出来的空间怎么分

假设横向容器的内容宽度为 600px，两个子项的基准宽度分别为 100px 和 200px，没有 margin、padding、border 和 gap，也不触发 min/max 限制：

.first { flex: 1 1 100px; }
.second { flex: 2 1 200px; }

剩余宽度为 600 - 100 - 200 = 300px。grow 系数之和为 3，第一个获得 100px，第二个获得 200px，最终宽度分别为 200px 和 400px。

grow 分配的是剩余空间，而不是直接规定最终宽度比例。把第二个的 basis 改成 100px 后，最终宽度约为 233.33px 和 366.67px，不再是 1:2。只有基准尺寸和其他条件合适时，才会得到最终尺寸的比例。

flex-shrink：不够的空间怎么扣

假设容器只有 300px，两个子项 basis 为 200px 和 400px，shrink 都为 1，且允许缩到计算结果：

.first { flex: 0 1 200px; min-width: 0; }
.second { flex: 0 1 400px; min-width: 0; }

总共需要减少 300px。收缩权重按 shrink × flex base size 计算，所以两项按 1:2 分担，分别减少 100px 和 200px，最后得到 100px 和 200px。相同的 shrink 值不表示各扣一半。

图标、头像和操作按钮通常需要保留尺寸，可使用 flex: 0 0 auto。Flex 默认允许收缩，仅设置 width 不一定能阻止元素被压窄。

flex-basis：分配前从多大开始

flex-basis 指定主轴方向的基准尺寸。row 中影响宽度，column 中影响高度。非 auto 的 basis 通常优先于同一主轴上的 width 或 height 参与 Flex 计算；最终尺寸还要经过伸展、收缩及最小最大尺寸限制。

写法 常见用途
flex: 0 1 auto Flex 项的初始行为，按内容或主轴尺寸作为基准，允许收缩
flex: 0 0 auto 或 flex: none 保持内容或指定尺寸，不伸展、不收缩
flex: 1 1 auto 或 flex: auto 以内容或指定尺寸为基准，再分配空间
flex: 1 1 0 以零长度为基准分配空间，适合比例布局
flex: 1 常用简写，浏览器通常采用 1 1 0%

在主轴尺寸不确定的容器里，0% 和长度 0 并不总是等价：百分比 basis 无法解析时可能按内容参与计算。不能只靠 flex: 1 让一个高度完全由内容决定的祖先突然拥有屏幕高度。

Compose 的 weight 也分配剩余空间，但没有 CSS shrink 那套规则。它要求处于 RowScope 或 ColumnScope，权重必须大于零，默认 fill = true。主轴约束无限时，例如放在同方向滚动容器内，也不能期待权重按有限屏幕空间工作。

四、常用 Flex 属性和 Compose 对照

.toolbar {
  display: flex;
  flex-direction: row;
  align-items: center;
  justify-content: space-between;
  gap: 16rpx;
}

对应的 Compose 排列方式如下。CSS 中的 gap 提供最小间隔，下面额外用 Spacer 表达这段固定间距：

Row(
    modifier = Modifier.fillMaxWidth(),
    horizontalArrangement = Arrangement.SpaceBetween,
    verticalAlignment = Alignment.CenterVertically,
) {
    Text("标题")
    Spacer(Modifier.width(8.dp))
    Button(onClick = {}) { Text("操作") }
}

以下对应关系按布局方向区分，不能把 Arrangement.Start 直接用于 Column 的垂直排列：

CSS 意图 Compose Row Compose Column
justify-content: flex-start horizontalArrangement = Arrangement.Start verticalArrangement = Arrangement.Top
justify-content: center Arrangement.Center Arrangement.Center
justify-content: flex-end Arrangement.End Arrangement.Bottom
justify-content: space-between Arrangement.SpaceBetween Arrangement.SpaceBetween
align-items: flex-start verticalAlignment = Alignment.Top horizontalAlignment = Alignment.Start
align-items: center Alignment.CenterVertically Alignment.CenterHorizontally
align-items: flex-end Alignment.Bottom Alignment.End
固定 gap Arrangement.spacedBy(8.dp) Arrangement.spacedBy(8.dp)
align-self: center 子项 Modifier.align(Alignment.CenterVertically) 子项 Modifier.align(Alignment.CenterHorizontally)

CSS align-items: stretch 没有直接等价的 Compose 参数。在高度有界的 Row 中，可按需要给子项 fillMaxHeight()；Column 中则是 fillMaxWidth()。align-self 和 Compose 的 align 都只影响当前子项，但 Compose 的 align 重载取决于 Row、Column 或 Box 作用域。

gap: 16rpx 与 8.dp 只是在此示意间距，不是通用换算关系。rpx 通常按屏幕宽度相对 750 换算，dp 按 Android 密度换算；大屏适配配置也会影响 rpx 的结果。

gap 在目标平台上的支持情况要按项目工具链验证。需要兼容性更稳定时，可以给相邻子项增加 margin-left 或 margin-top，但要避免首项也产生多余间距。

用例：长标题后面保留操作按钮

<template>
  <view class="task-row">
    <text class="task-row__title">一段很长的任务名称，需要在空间不足时显示省略号</text>
    <button class="task-row__action" size="mini">查看</button>
  </view>
</template>

<style scoped lang="scss">
.task-row {
  display: flex;
  align-items: center;
  width: 100%;
}

.task-row__title {
  flex: 1;
  min-width: 0;
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}

.task-row__action {
  flex: 0 0 auto;
  margin: 0 0 0 16rpx;
}
</style>
Row(
    modifier = Modifier.fillMaxWidth(),
    verticalAlignment = Alignment.CenterVertically,
) {
    Text(
        text = "一段很长的任务名称，需要在空间不足时显示省略号",
        modifier = Modifier.weight(1f),
        maxLines = 1,
        overflow = TextOverflow.Ellipsis,
    )
    Spacer(Modifier.width(8.dp))
    Button(onClick = {}) { Text("查看") }
}

按钮保持内容尺寸，标题接收剩余空间。省略号规则与 Flex 尺寸规则需要同时成立，仅写 text-overflow 不会限制元素宽度。

用例：两个区域按 1:2 分配宽度

.split {
  display: flex;
  gap: 16rpx;
}

.split__left { flex: 1 1 0; min-width: 0; }
.split__right { flex: 2 1 0; min-width: 0; }

两个子项的 padding、border 等条件相同时，可近似得到扣除 gap 后的 1:2 分配。Compose 对应：

Row(
    modifier = Modifier.fillMaxWidth(),
    horizontalArrangement = Arrangement.spacedBy(8.dp),
) {
    Text("左侧", modifier = Modifier.weight(1f))
    Text("右侧", modifier = Modifier.weight(2f))
}

用例：标签不足一行时换行

.tags {
  display: flex;
  flex-wrap: wrap;
  gap: 16rpx;
}

.tags__item {
  flex: 0 1 auto;
  max-width: 100%;
  overflow-wrap: anywhere;
}

Compose 使用 FlowRow：

FlowRow(
    modifier = Modifier.fillMaxWidth(),
    horizontalArrangement = Arrangement.spacedBy(8.dp),
    verticalArrangement = Arrangement.spacedBy(8.dp),
) {
    listOf("风景", "家庭相册", "最近上传").forEach { label ->
        Text(label)
    }
}

部分 Compose Foundation 版本使用 FlowRow 需要 ExperimentalLayoutApi 的 opt-in，应以项目依赖版本为准。

Flex 默认 nowrap，不会因为放不下就自动换行。align-items 管每一行内部的交叉轴排列；align-content 在多行且交叉轴有剩余空间时，管多行整体如何分布。Flex 是一维布局，每一行独立分配空间；需要各行各列严格对应时，应考虑目标端支持的 Grid 或明确的列宽规则。

五、uni-app 的滚动容器写法

不要让多个祖先同时负责滚动。页面滚动和局部滚动应明确选择一种。

下面使用一个 Flex 内容区承接剩余高度，再让 scroll-view 填满该区域。通过定位容器提供确定的滚动范围，减少直接依赖组件宿主 Flex 行为的情况。示例假设根容器可以占据完整页面视口：

<script setup lang="ts">
const items = Array.from({ length: 50 }, (_, index) => ({
  id: index,
  title: `任务 ${index + 1}`,
}));
</script>

<template>
  <view class="page">
    <view class="page__header">固定头部</view>
    <view class="page__body">
      <scroll-view class="page__scroll" scroll-y>
        <view class="page__list">
          <view v-for="item in items" :key="item.id" class="page__item">
            {{ item.title }}
          </view>
        </view>
      </scroll-view>
    </view>
    <view class="page__footer">底部工具栏</view>
  </view>
</template>

<style scoped lang="scss">
.page {
  display: flex;
  flex-direction: column;
  height: 100vh;
  min-height: 0;
  overflow: hidden;
}

.page__header,
.page__footer {
  flex: 0 0 auto;
  padding: 24rpx 32rpx;
}

.page__body {
  position: relative;
  flex: 1;
  min-height: 0;
  overflow: hidden;
}

.page__scroll {
  position: absolute;
  top: 0;
  left: 0;
  width: 100%;
  height: 100%;
}

.page__list {
  box-sizing: border-box;
  padding: 24rpx 32rpx;
}

.page__item {
  padding: 24rpx 0;
}
</style>

Compose 对应：

Column(modifier = Modifier.fillMaxSize()) {
    Text("固定头部", modifier = Modifier.padding(16.dp))
    LazyColumn(
        modifier = Modifier.weight(1f).fillMaxWidth(),
        contentPadding = PaddingValues(16.dp),
    ) {
        items(count = 50) { index ->
            Text("任务 ${index + 1}", modifier = Modifier.padding(vertical = 12.dp))
        }
    }
    Text("底部工具栏", modifier = Modifier.padding(16.dp))
}

.page__body 的 flex: 1 表示它应占据剩余空间；min-height: 0 允许它缩小到父容器分配的高度。内部 scroll-view 再占满这个有界区域。若使用页面自身滚动，则不必再嵌套一个同方向的 scroll-view。

这里的 scroll-view + v-for 与 LazyColumn 只是在功能上都提供列表滚动，不能认为渲染性能相同。普通 v-for 通常会创建全部条目；LazyColumn 按可见区域等需要组合和布局条目。长列表应另行选择目标平台支持的虚拟列表方案。

100vh 也不等于“扣除导航栏和 tabBar 后的剩余高度”。在 H5 浏览器工具栏、软键盘、自定义导航或嵌套页面容器中，应根据宿主分配的实际可用区域调整。需要安全区时由页面容器统一处理；Compose 中通常用 Scaffold 的 innerPadding 或 WindowInsets，避免重复叠加内边距。

参考项目中的实际结构

ai-album-uniapp 的 src/components/page-shell/index.vue 区分两类页面。下面只摘取相关样式，不作为独立组件代码：

.page-shell {
  position: relative;
  min-height: 100vh;
  box-sizing: border-box;
  overflow: visible;
}

.page-shell--static {
  display: flex;
  flex-direction: column;
  height: 100vh;
  min-height: 0;
  overflow: hidden;
}

.page-shell--static .page-shell__content {
  flex: 1;
  min-height: 0;
  overflow: hidden;
}

默认模式允许内容向下展开，由页面滚动；scrollable 为 false 时应用静态模式，限制页面高度，把剩余区域交给内容。该属性本身不会自动创建 scroll-view。模板另外有导航栏占位、fixed-footer 和 overlay 插槽；插槽名称本身也不等于 CSS 定位规则，实际定位仍取决于插入的元素。

因此，在这个项目里新增页面内容时，应先决定由页面滚动还是由内容组件局部滚动，再决定是否使用静态模式。不能给每一层都套 height: 100vh。

六、SCSS 组织建议

组件使用 scoped 时，根节点类名和子元素类名最好保持稳定：

.feature-card {
  display: flex;

  &__icon {
    flex: 0 0 auto;
  }

  &__content {
    min-width: 0;
    flex: 1;
  }

  &--disabled {
    opacity: 0.5;
  }
}

&__content 会编译为 .feature-card__content，&--disabled 会编译为 .feature-card--disabled；它们不是 .feature-card 的后代选择器。需要后代关系时写空格，例如 & .title。这与已有 SCSS 选择器文章中的规则一致。

建议把布局职责分成三层：页面根容器负责屏幕尺寸和页面级滚动；页面内容容器负责内边距和宽度；业务组件根容器负责组件内部的 Flex 或 Grid。这样组件移到另一个页面时，不需要依赖原页面的父选择器才能正常显示。

参考项目在 src/styles/_mixins.scss 定义了一个居中 mixin：

@mixin flex-center($direction: row) {
  display: flex;
  flex-direction: $direction;
  align-items: center;
  justify-content: center;
}

在支持项目 @ 路径别名的 SCSS 中，可按模块名引用：

@use '@/styles/mixins' as layout;

.empty-state {
  @include layout.flex-center(column);
  min-height: 400rpx;
}

它只复用一组声明，不创建组件，也不把子元素尺寸自动改成满宽。适合空状态或居中内容，不应无条件用于每个页面根节点。

七、排查布局问题的顺序

  1. 检查父元素是否提供可解析的尺寸：普通流中的 height: 100% 通常需要包含块具有确定高度；Flex、Grid 和绝对定位另有尺寸规则。页面根容器可按需求使用 min-height: 100vh 或有界的 height。
  2. 确认主轴方向：justify-content 的方向由 flex-direction 决定。
  3. 检查 Flex 子项是否需要 flex: 1、min-width: 0 或 min-height: 0。
  4. 检查是否存在两个同方向滚动容器，以及 overflow 是否把内容裁掉。
  5. 在 H5、微信小程序和 App 目标端分别确认 rpx、gap、伪元素和滚动行为。

CSS Flex 和 Compose 的概念可以互相映射，但测量模型并不完全相同。CSS Flex 综合包含块尺寸、内容的固有尺寸、基准尺寸和伸缩规则计算结果；Compose 由父布局向子项传递约束，子项报告尺寸后由父布局放置。遇到权重、滚动和最小尺寸问题时，应先确定可用空间和尺寸来源，再选择属性。
